# Test Final Report Template

```yaml
test_result_id: ...
request_id: ...
result: passed|passed_with_scope_limit|failed|inconclusive|blocked|request_more_context
feedback_kind: success|failure|inconclusive|blocked|missing_context|governance_blocker
final_code_ref: ...
implementation_candidate_ref: ...
test_plan_ref: ...
route_reports:
  - route_id: ...
    route_result: ...
    evidence_refs:
      - ...
test_data_refs:
  - ...
evidence_refs:
  - ...
coverage_summary:
  covered_scope:
    - ...
  uncovered_scope:
    - ...
failure_signatures:
  - ...
owner_hint:
  owner_type: group|integration|ambiguous|none
  owner_id: optional
blocker_kind: environment|dependency|handoff|candidate_material|governance|policy|unknown
blocker_scope: ...
requires_governance_review: false
required_next_action: ...
known_limits:
  - ...
assumptions:
  - ...
material_conditions:
  - ...
reproducibility_set_ref: ...
next_route: execution|final_review
status: test_evidence_candidate
```

## Interpretation

- `next_route: execution` is used for failed, inconclusive, blocked, or missing-context outcomes.
- `next_route: final_review` is used for passed or passed_with_scope_limit outcomes.
- The report is evidence and scoped conclusion. It is not global causal truth.

## Strict interpretation

- `failed` means evidence proves candidate failure.
- `owner_hint.owner_type: ambiguous` is valid with `failed`.
- Ambiguous owner does not make a proven failure inconclusive.
- `inconclusive` means evidence is not strong enough to prove pass or fail.
- `blocked` means testing cannot proceed due to missing prerequisite or governance/policy blocker.
- `blocker_kind: governance` requires `requires_governance_review: true`.
- `next_route: master` is invalid under the current topology.
