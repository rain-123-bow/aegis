# Causal Merge Contract

## Definition

Causal Merge applies reviewed causal deltas to produce a new canonical causal baseline.

## Merge source

Causal merge happens together with project branch merge semantics. Code, Archive, Knowledge, and Causal state are treated as one branch state.

## Merge preconditions

Before a causal delta is merged:

- Causal Review must be completed.
- Conflicts in the same condition set must be resolved.
- Accepted claims must have required fields.
- Status transitions must be explicit.
- Route/expand changes must be reviewed if they alter future reasoning priority.
- New version seal must be generated by Master-side authority.

## Merge results

Merge may produce:

- new active claims
- new tentative claims
- rejected proposals
- invalidated old claims
- superseded old claims
- scope-split records
- updated route guidance
- new causal version

## No silent rewrite

Existing causal claims must not be silently overwritten. Corrections must use status transitions, supersession, invalidation, or amendment-like update records.

## Versioning

Merging accepted deltas produces a new causal version.

```text
CGV0012 + reviewed delta -> CGV0013
```
