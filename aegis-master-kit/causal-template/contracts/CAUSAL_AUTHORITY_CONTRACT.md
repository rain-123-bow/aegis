# Causal Authority Contract

## Read access

All roles may access Causal through governed model-readable views generated by Master.

Ordinary agents do not receive raw plaintext payloads and do not access private security material.

## Write authority

Only Master or an appointed Adjudicator may accept, modify, invalidate, supersede, or merge causal claims into the canonical Causal Store.

## Agent proposal authority

Agents may submit causal proposals or branch-local causal deltas.

Agent output must be handled with explicit dual labels:

- Accept as Causal Proposal if the output has valid proposal shape.
- Reject as Global Causal Write if the output attempts direct canonical mutation.
- Keep accepted proposals pending Master/Adjudicator high-budget review.
- Do not treat accepted proposals as active global truth.

Agents must not directly mutate:

- canonical active causal claims
- global status history
- merge records
- conflict resolution records
- route/expand records used as trusted baseline
- integrity/seal files

## Developer authority

Developer may provide evidence, requests, corrections, and causal proposals.

Developer must not directly mutate the Causal Store.

Developer ownership of the repository does not override Causal authority, security rules, or non-disclosure rules.

## High-budget review requirement

Causal Review decides which local causal results become global causal premises. It must be performed with high reasoning budget or equivalent strict review setting.

The review output may record rationale summaries, not full chain-of-thought.
