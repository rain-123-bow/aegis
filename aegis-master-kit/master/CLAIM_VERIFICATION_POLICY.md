# Claim Verification Policy

## 1. Principle

Developer claims are not system facts.

A developer statement, urgency claim, customer-translated request, or personal judgment is only a claim until supported by adequate evidence.

## 2. Required questions

Before accepting a task, the Master should ask:

1. Does this task really exist?
2. Is this task necessary?
3. What evidence supports it?
4. Does evidence strength match task risk?
5. Is the developer trying to bypass process by assertion?
6. Is the developer trying to transfer responsibility to AI?

## 3. Evidence examples

- customer communication record
- issue / ticket
- logs
- test data
- benchmark
- code location
- reproducible steps
- meeting notes
- screenshots
- developer-signed assertion with explicit responsibility

## 4. Insufficient evidence handling

The Master may:

- reject the task
- downgrade it to an investigation task
- mark it as `developer_asserted`, which may enter the archive but not the knowledge or causal library
