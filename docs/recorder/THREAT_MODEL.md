# Aegis Recorder threat model

## Protected facts

The Recorder protects the byte order and forwarding state observed at one
owned app-server stdio boundary. It must preserve enough evidence to distinguish
these states:

- observed and not forwarded;
- forwarded and durably acknowledged;
- forwarding failed;
- forwarding may have happened but its acknowledgement is missing;
- stream ended cleanly;
- stream ended with an incomplete frame;
- journal ended with an incomplete record;
- child exited or was terminated;
- guard requested outer-Job termination;
- reclamation was independently confirmed or remains unconfirmed.

## Trust boundary

Trusted for the local transport contract:

- the running Recorder code and interpreter;
- the operator-selected deployer/bootstrap bytes and their expected digests;
- the already-open journal handle;
- the already-open guard supervision-sidecar handle;
- operating-system write and flush results;
- the child pipes created by the Recorder.

Not trusted as independent authority:

- the Master;
- agents;
- candidate repository content;
- caller-provided verdicts or event bytes;
- the local filesystem after capture;
- local wall-clock time;
- a signer or trust root supplied by the same candidate;
- Codex history, rollout JSONL, SQLite, hooks, or post-hoc file tailing.
- synthetic conformance scripts, model namespaces, and event logs.

## Fail-closed rules

1. No target creation before the journal header, start entry, and spawn request
   are durably synced; no target instruction executes before suspended-process
   containment, guard-main authorization, and durable resume intent.
2. No frame forward before its observation entry is durably synced.
3. No clean terminal state while an observation lacks one decisive forwarding
   result; `FORWARD_OUTCOME_UNKNOWN` is non-decisive.
4. No evidence repair, truncation, or overwrite by the verifier.
5. No automatic replay of an unresolved observation.
6. No `authority_verified=true` in this implementation.
7. No Windows `PASS` without a valid journal-bound supervision sidecar and
   `NORMAL_SUPERVISION_COMPLETED`.
8. No reclamation claim from a termination request, API success, elapsed time,
   or Job-handle close alone.

## Residual authority blocker

A production authority claim requires a separately operated append-only sink
or signer with:

- preauthorized policy and trust root outside the candidate and Master;
- monotonic provider position;
- provider committed time;
- signed checkpoint over the exact final journal digest and session identity;
- independent retrieval or inclusion proof;
- revocation and key-rotation rules;
- a second verifier that does not trust Recorder-local configuration.

The standalone local Recorder is useful evidence infrastructure before that
adapter exists. It is not the missing external authority by itself.
