## 2. 不可丢失的设计语义

### 2.1 系统目标

Aegis 不是普通代码代理包装器。目标是通过多智能体协同、对抗审核、价值目标分离、职责分离和证据解释权分离，形成可恢复、可追责的工程治理系统。

成果是否通过审核或测试，不影响审核者、测试方案作者、测试执行者的工作评价。各角色只对自身工作的完整性和严谨性负责。这一分离用于避免产出者为维护自身成果评价而与代码结果自洽。

### 2.2 Master 的设计演进

旧设计把 Master 做成独立 LangGraph 模块，由多个子智能体分别编写需求、方案、代码和审核意见。该设计已废弃。

废弃原因：需求、方案、代码之间要求最高语义精度；通过窗口代理转述会损失语义，并增加同步时间和资源。现行设计由 Master 直接编写需求、实现方案和代码，并直接记录推理事实；独立子智能体只审核或取证。

Master 是用户意图的长期语义执行者，不是 A-F 节点。Master 同时是代码执行者。需求审核与方案审核可以由同一独立审核者完成；方案审核必须把冻结需求作为输入。逻辑上一个或两个审核者等价，实际配置可在保持独立性的前提下调整。

### 2.3 审核者不知道流程拓扑

多 agent 流程必须真实创建并调用多个独立子 agent，保留角色身份、独立线程、实际调用和输出证据。禁止由主 agent 扮演多个角色并生成模拟审核或取证记录。

审核者和 A-F 角色不得知道其他角色、节点、接收者或流程方向。角色之间禁止自由通信，禁止串供。角色只读取协调器提供的冻结输入，只写自己的报告。

审核输出不得包含 `RETURN_TO_A`、`RETURN_TO_C` 或任何等价的接收者/路由语义。允许的输出是事实结论，例如通过、证据缺失、需求缺陷、实现方案缺陷、测试方案缺陷、执行证据缺失、未判定。协调器私下把事实类别映射为下一处理阶段。

审核者不得修改任何上游产物。底层为生成本角色报告而创建文件是允许的；需求、方案、测试方案、代码、测试证据和其他角色报告只能读取和引用。

### 2.4 四类审核职责

1. Master 审核：审核 Master 编写的需求和实现方案，只给意见，不修改原文。被审核物通过或拒绝不影响审核工作的评价。
2. 测试方案审核：审核 A 的测试方案，原则同 Master 审核。
3. D 证据审核：同时读取需求、实现方案、测试方案和测试数据；判断方案是否完整、执行是否严格、结论是否有证据。D 只报告事实类别，不知道协调器将把缺陷交给哪个处理阶段。
4. F 终审：审核整个工程，包括需求、方案、代码、测试方案、测试结果、原始证据、推理库、项目封印和治理流程。

F 失败后必须给出明确结论、原因和证据索引。Master 只验证 F 结论的结构和证据真实性；确认无误后递交用户。Master 不能覆盖 F 结论。

### 2.5 A-F、恢复与复用

A-F 始终存在。E 失败不得进入 F。

角色线程是项目级长期资源，保留中间状态，不要求每次重跑完整流程。故障线程可以关闭并重新创建；恢复只能依赖冻结产物、角色技能和推理库，不能依赖隐含聊天上下文。

Master 修复代码后：

- 需求和实现方案均未变化：保留已批准测试方案，创建新运行并从 C 开始。
- 需求或实现方案任一变化：创建新运行并从 A 开始。
- 旧运行、测试方案、报告、失败结论和证据永久保留，不覆盖。

重复拒绝修复按基础语义单元判断，不按文本或问题编号判断。相同“前提、推理关系、结论、证据缺口、替代解释”被反复提交，且被审核者拒绝补证、收窄结论或修正推理，才构成重复拒绝修复。

### 2.6 冻结与追责

A-F 运行期间，需求、方案、代码、运行范围、相关推理事实和项目封印禁止变化。发生任何变化必须立即终止运行，封存路径、旧新摘要、时间和可用进程证据，并要求用户说明原因。

记录原因只解除同项目新运行的启动阻塞，不能复活旧运行，不能改变旧失败结论。

任何会影响生产编译结果、启动方式、执行路径、输入解释或外部行为的文件都属于关键运行范围。测试、演示、示例、基准和文档默认排除；如果生产路径实际加载它们，则必须纳入。

### 2.7 `.aegis` 和推理库

`.aegis/` 的唯一目的，是承载项目特化推理库实例及其证据、可重建索引和上下文包。它跟随项目同步，用于消除人类开发者或本地智能体对项目认知背景的垄断。

运行状态、租约、线程注册、检查点、TraceRelay 日志、原始响应和临时文件必须位于项目外的运行根目录。

推理库采用第一性实现：

- PostgreSQL 16 或更高版本保存不可变事实版本、关系、事件和当前投影。
- pgvector 0.8.0 或更高版本只作为可重建语义索引；权威事实不依赖向量行。
- 全文检索提供精确术语候选；向量检索提供语义候选；因果图展开提供原因、约束、支持、反驳和影响闭包。
- 项目锚点绑定项目、数据库集群、数据库对象和模式；目录签名证明实际数据库结构。
- 上下文包只证明查询和因果闭包可重放，不宣称需求或环境已经完整覆盖。
- 空库和零命中查询合法，但仍必须绑定项目、快照、查询和规范摘要。

### 2.8 独立组件

AegisSealCore 负责对调用方批准的运行范围生成确定性 ASC-1 封印。范围选择由 Aegis 负责；核心只接受规范化相对文件条目。源码仓库：`git@github.com:rain-123-bow/AegisSealCore.git`，当前归档提交：`ae1f17b1eb5cedafdda309b41a8f7c17cd114043`。

TraceRelay 是第三方风格的独立软件开发工具包，不是子模块。源码仓库：`git@github.com:rain-123-bow/TraceRelay.git`。本仓库快照绑定上游提交 `9775e26e6f0999a7047e0cff72e13c62da99c065`。

受保护远程见证已经获得机制授权，但发布顺序不能改变：范围审核、用户确认、范围决定、受治理提交、项目封印、运行权威，最后才是受保护远程见证。

### 2.9 模型与费用边界

系统只保证 Codex/GPT 模型边界；其他模型的理解偏差不属于验收标准。同模型对抗审核足够，不要求跨模型审核。

禁止未授权降级模型、推理预算、质量门禁或证据机制。任何产生外部费用的模型调用、远端服务或付费资源必须由用户单独授权。

2026-09-05 用户明确要求：后续开发测试中创建的子智能体，推理预算使用 `high` 或更低。该限制适用于本任务的测试调用；创建前必须显式核对有效 effort，不能直接沿用旧 F 模板的 `xhigh`。本轮不更改产品默认角色模板，不修改历史线程、冻结运行或已有验收记录；模型选择和质量门禁保持原约束。
